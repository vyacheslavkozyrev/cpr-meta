> **Resolved: Major conflict – error response format.** F0006 adopts the existing custom error envelope `{"error": {"code": "...", "message": "...", "details": [...]}}` used by F0004 and F0005. All error shapes in `api.md` that reference RFC 7807 ProblemDetails are superseded by this format. No migration or changes required to F0004/F0005.
>
> **Resolved: Major conflict – pagination field name.** The `GET /api/review-cycles` query parameter `per_page` (from `api.md`) is renamed to `page_size` to match F0005's existing implementation. All other pagination fields (`page`, `sort_dir`, `data`, `pagination`) remain as specified.

## Rationale

The single migration (T001) opens the plan because the three new tables must exist before EF Core configurations can reference their columns, and the partial unique indexes on `review_nominees` and `review_responses` enforce duplicate-prevention rules at the database level as a safety net beneath service-layer checks. Domain enums (T002–T003) precede entity definitions (T004–T006) because `ReviewCycle.Status` and `ReviewNominee.Status` property types must compile before the entity classes are processed; `ReviewCycleStatus.IsValidTransition` is co-located on the enum rather than the service to keep state-machine rules close to the type they guard. Both `IReviewCycleRepository` (T007) and `IReviewCycleService` (T008) are defined before their implementations (T016–T017) so Application and API layers compile independently of Infrastructure — this also allows mocking in tests. The service implementation (T017) is deliberately sequenced after the repository implementation (T016) since `ReviewCycleService` injects `IReviewCycleRepository`. Both Major conflicts from the Analyze phase are closed in this plan's header section: `page_size` replaces `per_page` throughout for F0005 consistency, and the custom `{"error":{…}}` envelope replaces RFC 7807 ProblemDetails to match existing error middleware in F0004/F0005. On the frontend, mock data (T024) precedes MSW handlers (T025) so response bodies reference typed fixture objects directly; `CycleStatusBadge` (T027) is built before the forms and panels that embed it; leaf components (T027–T032) are complete before the page components (T033–T036) that compose them; i18n keys (T037) and route registration (T038) are last in the UI group because the full string surface area and page export names are only known after all components are defined.
